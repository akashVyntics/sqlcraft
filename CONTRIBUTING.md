# Contributing

Use one `section/<name>` branch per section, based on the previous reviewed checkpoint. Open a pull request with the concrete behavior, validation and any hosting prerequisites. Keep generated files current, avoid unrelated changes, and do not commit secrets, user data or production databases.

Provide English and Hinglish for every question, hint and explanation. Prefer original business scenarios and synthetic data. Link reference curricula; do not import proprietary statements or datasets without an appropriate license.

Run the relevant integration and browser checks. Test authorization failures, cross-account access, invalid input, edge cases and recovery rather than just a happy path. Do not remove security controls to make a check pass. Review dependency updates and rerun checks when updating the lock.
